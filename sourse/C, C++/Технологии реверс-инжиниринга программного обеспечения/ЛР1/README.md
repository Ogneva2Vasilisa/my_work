## Средства защиты

**Реализованная программа использует следующие общие подходы к защите ПО:**

a.           Хранение в зашифрованном виде всех строк, в т.ч. выводимых на экран.
b.          Проверка и вывод информации в разных местах программы.
c.           Контроль целостности участков кода, ответственных за проверку «пароля» (подсчет CRC исполняемого кода функции проверки пароля **в оперативной памяти** во время выполнения программы).
d.          Наличие нескольких проверок пароля в разных местах программы.
e.           Наличие ложных проверок (в т.ч. сразу после считывания «пароля»).
f.           Использование методов запутывания кода для усложнения анализа кода программы.

**Реализованная программа использует:**

a.         Не менее 4 методов обнаружения средств отладки и противодействия им. (```IsDebuggerPresent```,  Hardware Breakpoints, PAGE_GUARD, проверка флага перехвата)
b.         Не менее 3 методов противодействия дизассемблированию. (Применение инструкции ```__emit``` Использование jz и jnz, ведущих на одну метку, Jump Instruction with a Constant Condition)
c.         Не менее 2 методов выявления виртуальных машин. (проверка ключей реестра, Выявление виртуальной машины по mac адресу)
d.         Фрагменты самомодифицирующегося кода (ниже)

``` C
int WriteMe(void* addr, int wb) {
       HANDLE
             h = OpenProcess(PROCESS_VM_OPERATION | PROCESS_VM_WRITE,
                    true, GetCurrentProcessId());
       return WriteProcessMemory(h, addr, &wb, 1, NULL);
}

void selfcode() {
       _asm {
             push 0x74; JMP >> JZ
             push offset Here
             call WriteMe
             add esp, 8
             Here: JMP short Here
       }
}
```

Также была применена защита от отладки путем просмотра открытых окон, обфускация кода c помощью проектов obfinsider и obfuscate для Visual studio, упаковка исполняемого файла с помощью UPX и ASPack
